# Apple-Inspired UI Design Checklist

## 1. Clarity
- [ ] Can users identify the page purpose quickly?
- [ ] Is the primary action obvious?
- [ ] Is the information hierarchy clear?
- [ ] Are labels concise and understandable?

## 2. Content
- [ ] Is the important content visually dominant?
- [ ] Are decorative elements competing with the content?
- [ ] Is whitespace helping grouping and readability?

## 3. Consistency
- [ ] Are spacing, typography, colors, and radii consistent?
- [ ] Are repeated interactions implemented consistently?
- [ ] Are existing components reused where appropriate?

## 4. Restraint
- [ ] Can unnecessary borders, cards, shadows, or colors be removed?
- [ ] Does each visual element serve a purpose?
- [ ] Is the design minimal without losing useful information?

## 5. Interaction
- [ ] Do actions provide immediate and understandable feedback?
- [ ] Are loading, success, error, and disabled states covered?
- [ ] Can users cancel or recover where appropriate?
- [ ] Are destructive operations protected?

## 6. Accessibility
- [ ] Are controls keyboard-accessible?
- [ ] Is focus visible?
- [ ] Is contrast sufficient?
- [ ] Are labels and semantic roles correct?
- [ ] Is color not the only way to communicate status?
- [ ] Is reduced motion respected?

## 7. Responsive Design
- [ ] Does the layout adapt to smaller screens?
- [ ] Are text wrapping and overflow handled?
- [ ] Are touch targets usable?
- [ ] Does the primary task remain accessible?

## 8. Final Review
- [ ] Has the implementation been visually inspected when possible?
- [ ] Have relevant interactions been tested?
- [ ] Are there any placeholder elements or broken states?
- [ ] Are remaining limitations documented?
