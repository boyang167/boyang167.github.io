# 计算机网络

## http

HTTP - 超文本传输协议， Hypertext Transfer Protocol

* 在HTTP中，客户端总是通过建立一个连接与发送一个HTTP请求来发起一个事务
* HTTP协议是无状态的，同一个客户端的这次请求和上次请求是没有对应关系的，对HTTP服务器来说，它并不知道这两个请求是否来自同一个客户端。为了解决这个问题， Web程序引入了Cookie机制来维护连接的可持续状态。

http: 是一种用于在网络上传输数据的协议。它是一种客户端-服务器协议，通常用于从Web服务器请求并获取网页，图片，视频和其他资源。

HTTP有一个明显的问题，它的数据传输是明文的，容易被窃听和篡改。为了解决这个问题，SSL/TLS技术应运而生。

**SSL（Secure Sockets Layer）和其继任者TLS（Transport Layer  Security）是一种加密通信协议，用于保护数据在网络上的传输安全性。SSL最初由Netscape公司开发，后来演化为TLS，成为Internet通信中的标准安全协议。**

**SSL/TLS使用加密技术将通信数据进行加密，使得第三方无法轻易窃听或篡改数据。在建立SSL/TLS连接时，客户端和服务器之间的通信将加密，确保数据的机密性和完整性。SSL/TLS ****握手阶段和加密阶段**是SSL/TLS协议中非常关键的两个阶段，它们负责建立安全连接、协商加密算法和密钥交换。

## SSL/TLS

### SSL/TLS 握手阶段

**SSL/TLS 握手阶段是安全连接的建立阶段，它确保通信的两端是合法的并且协商好了用于后续数据加密和完整性保护的密钥。**

1. **客户端Hello：** 握手开始时，客户端向服务器发送一个随机数（ClientHello）、支持的SSL/TLS版本、支持的加密算法和压缩方法等信息。
2. **服务器Hello：**  服务器收到客户端的ClientHello后，从中选择一个支持的SSL/TLS版本、加密算法和压缩方法，并生成一个随机数（ServerHello）。服务器还会发送服务器证书（包含公钥）、服务器的数字签名以及用于密钥交换的临时公钥（如果使用非RSA密钥交换算法）。
3. **验证证书：** 客户端在收到服务器证书后，会验证证书的合法性，包括检查证书的有效期、颁发机构的信任等。如果验证失败，握手将终止。如果验证通过，客户端会生成一个预主密钥（Pre-Master Secret）并用服务器的公钥加密发送给服务器。
4. **生成主密钥：** 服务器收到客户端的预主密钥后，使用自己的私钥解密并生成主密钥（Master Secret）。此时，客户端和服务器都拥有相同的主密钥，但这个主密钥仍然是加密的，因为它是从客户端的预主密钥生成的。
5. **生成会话密钥：** 客户端和服务器都使用主密钥来生成会话密钥（Session Key）。会话密钥是对称密钥，用于后续的数据加密和解密。
6. **握手完成：** 握手阶段完成后，客户端和服务器之间的通信将使用协商好的加密算法和会话密钥进行加密和解密。握手完成后，SSL/TLS连接建立成功。

### SSL/TLS 加密阶段

**SSL/TLS 加密阶段是建立在握手阶段之后的，它确保数据在传输过程中的机密性和完整性。**

1. **记录协议：** SSL/TLS将要传输的数据分割成小的记录（Record）块，每个记录块包括一个头部和一段数据。记录头部包含有关记录的信息，例如记录类型（数据、握手、警告等）和记录长度。
2. **数据加密：** 在记录协议的基础上，SSL/TLS使用协商好的加密算法（通常是对称加密算法，如AES）对记录的数据部分进行加密。只有拥有会话密钥的客户端和服务器才能进行正确的解密。这确保了数据在传输过程中的机密性。
3. **MAC（消息认证码）：** 为了保证数据的完整性，SSL/TLS使用MAC算法对记录的数据部分进行签名。这个签名随着记录一起传输，接收方使用会话密钥来验证数据的完整性，以防止数据在传输过程中被篡改。
4. **记录压缩（可选）：** 在加密之前，SSL/TLS还可以对数据进行压缩，以减少传输数据的大小。不过，由于一些安全性问题，现代SSL/TLS实现通常不再使用压缩。

**总结来说，SSL/TLS 握手阶段负责建立安全连接、协商加密算法和密钥交换，而SSL/TLS 加密阶段则负责实际的数据加密和完整性保护。这两个阶段共同确保了在互联网上的安全通信。**

### SSL/TLS 握手 和 TCP/IP 三次握手的区别

**SSL/TLS 握手和TCP/IP的三次握手是两个完全不同的过程，尽管它们在某种程度上都涉及到建立连接，但目的和实现方式不同。下面是它们之间的主要区别：**

**1. 目的不同：**

1. **SSL/TLS 握手**的主要目的是建立一个安全的通信通道，确保数据在传输过程中的机密性和完整性，同时协商加密算法和密钥交换方式。SSL/TLS 主要用于加密通信，如HTTPS。
2. **TCP/IP 三次握手**的主要目的是建立一个可靠的数据传输通道，确保数据能够可靠地从发送方传输到接收方。TCP/IP 主要用于可靠的数据传输，如HTTP、FTP等。

**2. 建立连接的方式不同：**

1. **SSL/TLS 握手**使用了非对称密钥和对称密钥的结合。在握手阶段，客户端和服务器交换公钥，然后生成一个共享的对称密钥，用于后续的数据加密和解密。这个过程是复杂的，涉及到公钥基础设施和数字证书。
2. **TCP/IP 三次握手**使用了简单的三步过程，用于建立可靠的数据传输通道。客户端发送一个SYN（同步）请求，服务器回复一个SYN-ACK（同步-确认）响应，最后客户端发送一个ACK（确认）响应，建立连接。这个过程是相对简单的，不涉及加密或密钥交换。

**3. 安全性不同：**

1. **SSL/TLS 握手**是为了提供安全性而设计的，确保通信双方之间的数据不会被窃听或篡改。它使用了复杂的加密算法和密钥交换机制，以保护通信的机密性和完整性。
2. **TCP/IP 三次握手**主要是为了建立可靠的数据传输通道，而不涉及数据的加密或完整性保护。它的主要目标是确保数据能够可靠地传输，但不提供安全性。

**总之，SSL/TLS 握手和TCP/IP 三次握手是两个不同的过程，分别用于不同的目的。前者用于建立安全的通信通道，后者用于建立可靠的数据传输通道。**

### 为什么需要HTTPS？

**HTTPS的主要目的是保护用户和网站之间的数据安全。当你在使用HTTPS连接的网站上输入敏感信息，例如登录凭据或信用卡号码时，这些信息将被加密传输，使其难以被窃听。**

**此外，HTTPS还提供了网站身份的验证。用户可以通过查看浏览器地址栏上的锁定图标或网站的数字证书来确认他们连接到的是一个受信任的网站，而不是一个恶意网站。**

**HTTPS解决了以下几个重要问题，这些问题在HTTP中存在，而HTTPS通过加密和身份验证机制来解决它们：**

1. **数据加密**：HTTP传输的数据是明文的，容易被中间人窃听或篡改。HTTPS通过使用SSL/TLS协议，对数据进行加密，确保数据在传输过程中无法被窃听，保护用户隐私和敏感信息的安全。
2. **身份验证**：在HTTP中，服务器无法验证客户端的身份，也就是无法确定用户是否与他们通信的网站真实的服务器进行通信。HTTPS通过数字证书，确保客户端正在与合法的服务器通信，减少了中间人攻击的风险。
3. **数据完整性**：HTTP通信不提供数据完整性保护。攻击者可以在传输过程中篡改数据，导致内容损坏或潜在的安全漏洞。HTTPS通过使用加密哈希算法，确保数据在传输过程中没有被篡改，保持数据的完整性。
4. **信任和SEO**：HTTPS网站通常受到更多的信任，因为它们提供了更高级别的安全性。搜索引擎（如Google）将HTTPS网站排名得更高，这对于网站的SEO（搜索引擎优化）非常重要。
5. **遵守法规和标准**：一些法规和标准要求在网站上处理敏感数据（如信用卡信息、医疗记录等）时使用HTTPS来确保数据的保护。遵守这些法规对于企业和网站来说是必要的。

**总的来说，HTTPS解决了HTTP存在的不安全性和隐私问题，为网站和用户提供了更高级别的保护，增加了信任度，并满足了法规和标准的要求。因此，HTTPS已经成为保护隐私和数据安全的标准协议，几乎所有的网站都应该考虑使用它来提供更安全的在线体验**

### HTTP 、SSL/TLS、HTTPS 、TCP/IP 之间的关系

**HTTP、SSL/TLS、HTTPS和TCP/IP是在网络通信中密切相关的协议和概念，它们之间的关系如下：**

1. **TCP/IP（Transmission Control Protocol/Internet Protocol）**：
2. **TCP/IP是互联网通信的基础协议套件，它包括多个协议，其中包括TCP（Transmission Control Protocol）和IP（Internet Protocol）。**
3. **IP协议负责在网络中寻址和路由数据包，而TCP协议负责在网络上建立可靠的连接，确保数据的可靠传输。**
4. **HTTP（Hypertext Transfer Protocol）**：
5. **HTTP是一种应用层协议，它建立在TCP/IP协议之上。HTTP定义了Web浏览器和Web服务器之间的通信规则**
6. **当您在浏览器中输入URL并按下回车时，浏览器会使用HTTP协议向Web服务器请求网页，然后服务器会响应并返回请求的网页。**
7. **SSL/TLS（Secure Sockets Layer/Transport Layer Security）**：
8. **SSL/TLS是用于加密和保护网络通信的安全协议，它工作在传输层。**
9. **SSL/TLS用于在客户端和服务器之间建立安全通信通道，确保数据的机密性和完整性。它不仅可以用于保护HTTP通信，还可以用于保护其他应用层协议的通信。**
10. **HTTPS（HTTP Secure）**：
11. **HTTPS是HTTP协议和SSL/TLS协议的结合，用于创建安全的Web通信。**
12. **在HTTPS中，HTTP通信被加密，从而提供了数据的机密性和完整性保护。这使得通信双方可以在互联网上安全地传输敏感信息，如登录凭据、信用卡号等。**
13. **HTTPS的URL通常以"https://"开头，端口号为443。当您访问一个以HTTPS开头的网站时，您的浏览器会使用SSL/TLS协议来与服务器建立安全通信。**

**综上所述，TCP/IP是底层的协议套件，提供了网络通信的基础。HTTP是应用层协议，建立在TCP/IP之上，用于定义Web通信规则。SSL/TLS是传输层的安全协议，用于加密和保护通信。HTTPS是HTTP和SSL/TLS的结合，用于创建安全的Web通信通道。因此，HTTPS通常包括了HTTP、SSL/TLS和TCP/IP协议的功能，以确保安全的Web浏览和数据传输。**

### HTTPS是用的非对称加密吗？

**HTTPS在通信过程中使用对称加密和非对称加密的组合，以充分利用两者的优点，并解决各自的缺点。这个过程包括：**

**1. 建立连接阶段：在HTTPS通信开始时，首先需要建立安全的连接，这个阶段主要使用非对称加密，通常基于RSA算      法。这是因为非对称加密提供了身份验证和密钥交换的功能。在这个阶段，以下事情发生：**

1. **客户端向服务器发送一个请求，请求建立安全连接。**
2. **服务器将其公钥（公开的加密密钥）发送给客户端。**
3. **客户端使用服务器的公钥加密一个随机生成的对称密钥，并将其发送回服务器。**
4. **服务器使用其私钥（私有的解密密钥）解密客户端发送的消息，从中获取对称密钥。**
5. **此时，客户端和服务器都拥有相同的对称密钥，用于加密和解密后续的通信。**
6. ****数据传输阶段**：一旦建立了安全连接，HTTP的数据传输阶段就会开始。在这个阶段，主要使用对称加密，通常基于AES（高级加密标准）等算法。对称加密非常快速，因此适用于加密和解密大量数据。
7. **客户端和服务器都使用之前协商好的对称密钥来加密和解密数据，保护通信内容的机密性和完整性。**
8. **使用这种对称和非对称加密的组合方式，HTTPS克服了各自的限制：**
9. **对称加密**速度快，但密钥分发困难。因此，通过非对称加密安全地交换对称密钥，解决了这个问题。
10. **非对称加密**确保了通信双方的身份验证和密钥交换，但速度较慢。因此，只在连接建立时使用，之后的数据传输使用快速的对称加密。

**这种组合方式使得HTTPS能够提供安全、高效的数据传输，确保您的网络通信在保密性和完整性方面都能够得到保护。**
