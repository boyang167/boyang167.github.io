# 全站视觉系统与页面质感优化设计

## 目标

在不改变现有内容来源、导航结构和 Astro 静态架构的前提下，统一全站视觉语言，提升专业度、阅读体验和页面完成度。

设计方向为“高级编辑感 + 工程秩序”：保留现有蓝灰品牌基础，通过更准确的排版、留白、表面层级、细线和克制动效，减少模板感与视觉噪声。

## 范围

覆盖：

- 全局设计 tokens 与基础组件
- Header、Footer、按钮、卡片、标签和表单控件
- 首页
- 关于我
- 博客列表与文章详情
- 笔记列表与详情
- 知识库列表与详情
- Skill 列表与详情
- 深色模式、响应式和可访问性

不包含：

- 导航栏目重组
- 内容源、Markdown 结构或发布流程变更
- 新增客户端框架、UI 组件库或动画依赖
- 大规模文案重写

## 设计原则

1. 内容优先：视觉层级服务于阅读和信息扫描。
2. 系统一致：同类组件在不同页面使用同一套尺寸、状态和语义。
3. 克制质感：减少高频边框与阴影，依靠表面、留白和排版区分层级。
4. 工程秩序：编号、分类、元信息和流程结构保持明确。
5. 响应式优先：桌面充分利用宽度，移动端不压缩可读性。
6. 可访问：焦点、对比度、触控尺寸和 reduced-motion 完整覆盖。

## 全局设计系统

### 色彩

- 背景：冷白到浅蓝灰的低对比渐变。
- Surface：基础、抬升、强调三层表面。
- 主色：品牌蓝，用于链接、状态、图标和关键数字。
- 深色：海军蓝，用于主 CTA 与高对比标题。
- 文字：主文字、次文字、辅助文字三级对比。
- 语义色：成功、警告、危险仅用于明确状态，不用于装饰。

### 排版

- 保留 DM Sans 与 Noto Sans SC。
- 标题降低过紧字距，建立稳定的 H1–H4 比例。
- 正文提高颜色对比，中文行高保持 1.75–1.85。
- 正文最大阅读宽度为 720–780px；技术表格和图示可突破正文宽度。
- 元信息、eyebrow 和标签使用更稳定的字号与字距。

### 间距与尺寸

- 使用 4px 基准间距体系。
- 页面 section 间距分为 56 / 72 / 96px。
- 圆角分为 10 / 16 / 24px。
- Header、按钮、输入框和触控区域保持至少 40–44px 高。
- 内容最大宽度按页面类型区分：列表与营销页更宽，文章正文更窄。

### 表面与阴影

- 默认卡片使用浅表面 + 细边框。
- 仅关键卡片使用轻阴影。
- Hover 通过边框、背景和 1–2px 位移表现，不使用强烈放大。
- 深色模式使用独立 surface 层级和透明度，不简单反相。

## 全局组件

### Header

- 改为轻量 sticky header。
- 桌面端压缩高度，保留品牌、导航、语言、主题和联系入口。
- 滚动时使用半透明背景、轻 blur 与底部细线。
- Active 状态减少大面积填充，使用轻背景和更明确文字对比。
- 移动端菜单使用完整宽度面板，保证焦点与触控体验。

### Footer

- 缩小垂直占用。
- 保留版权、站点理念和返回顶部。
- 与正文通过细线和留白分隔，不使用额外卡片。

### 按钮与链接

- Primary、Secondary、Tertiary 三种等级。
- 统一圆角、高度、图标间距与 hover/focus 状态。
- 文本链接统一箭头动效和焦点样式。

### 卡片与标签

- 卡片分为内容卡、导航卡和强调卡。
- 标签区分分类、状态和技术关键词，避免所有标签使用同一视觉。
- 技术 chip 减小阴影，提升文字对比和横向密度。

### 表单与筛选

- 搜索框、筛选按钮和数量统计组成统一工具条。
- 移动端允许横向滚动分类或自然换行，不压缩文字。
- 输入框提供明显 focus 状态和清除动作空间。

## 页面设计

### 首页

- 压缩首屏高度，强化定位文案、CTA 和技术方向。
- 右侧品牌视觉保持低饱和系统感。
- Personal Knowledge System 改为精致导航面板，统一入口层级。
- 精选文章卡片强化分类、标题、摘要、日期和阅读时长层级。
- 桌面端首屏与精选内容形成连续视觉节奏。

### 关于我

- 保留当前 AI × Data × CMC 品牌定位。
- 统一 Agent、Data、ML、Full-Stack、Platform 等能力区块。
- 编号、分组标题、说明与技术 chip 使用一致结构。
- 减少大面积浅灰容器，提升横向利用率与内容呼吸感。
- 经历、方法论和 CTA 与全站卡片体系对齐。

### 博客列表

- Hero 更紧凑，明确发布数量和页面定位。
- 筛选和搜索组成单一工具条。
- 年份作为分组锚点，不与内容卡争夺视觉。
- 文章列表减少厚重边框，强化标题、摘要、分类和时间。
- 长标题和长摘要保持稳定截断与响应式布局。

### 笔记与 Skill 列表

- 使用与博客一致的页面 Hero、工具条、卡片和空状态。
- 笔记强调主题与来源；Skill 强调用途、类型和可复用性。
- 统一数量、分类和更新时间格式。

### 知识库列表

- 强化“目录—分类—条目”三级层级。
- 分类标题成为可扫描锚点，条目采用紧凑列表卡。
- 日期格式统一为 `YYYY.MM.DD`，不显示完整 GMT 字符串。
- 桌面端保持高信息密度，移动端保持单列与清晰分组。

### 文章、笔记、知识库与 Skill 详情

- 建立统一阅读壳层：标题、摘要、元信息、正文、目录和返回入口。
- 正文控制最佳阅读宽度。
- 优化标题、段落、列表、引用、链接、代码块、表格和分隔线。
- 图片统一圆角、说明和最大宽度。
- Mermaid、宽表格和代码块允许局部横向滚动。
- 桌面目录 sticky，移动端改为可折叠或正文前目录。
- 改善长文中的段落节奏、锚点定位和返回顶部体验。

## 动效

- 页面不增加入场动画。
- Hover、导航状态和箭头使用 120–200ms 过渡。
- Sticky Header 的背景与边框使用平滑状态变化。
- `prefers-reduced-motion` 下关闭位移与非必要过渡。

## 响应式

- 1440px 以上：内容画布充分展开，文章正文仍限制行宽。
- 960–1439px：保持双栏或三栏的可读比例。
- 650–959px：减少列数，保留工具条和导航可用性。
- 650px 以下：单栏布局，压缩 section 间距，保证 44px 触控区域。
- 全站不得出现页面级横向滚动；仅代码、表格和图示容器可局部滚动。

## 实现策略

1. 在 `BaseLayout.astro` 中整理全局 tokens 和基础组件样式。
2. 在 `Header.astro` 中完善 sticky、滚动态和移动菜单。
3. 按首页、列表页、详情页、关于页顺序适配页面样式。
4. 优先复用现有 class；必要时增加语义 class，不引入 UI 库。
5. 保持现有中英文切换逻辑，新增文案时同步映射。

## 验证标准

- `npm run build` 成功。
- 最近编辑文件无新增 IDE lint 错误。
- 首页、About、Blog、Notes、Knowledge、Skill 的列表和详情页均完成视觉检查。
- 中文与英文模式无明显布局破坏或未翻译新增文案。
- 浅色与深色模式的文字和控件对比清晰。
- 1440px、1024px、768px、390px 视口无页面级横向溢出。
- 键盘焦点、移动菜单、搜索和筛选控件可用。
- 文章代码块、表格、图片和 Mermaid 在桌面与移动端可读。
