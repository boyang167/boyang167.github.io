# 个人知识库迁移与网站集成设计

## 目标

将 `A:\17-workspace\3-TechNotes` 中所有可阅读的 Markdown 技术资料迁入个人网站仓库 `A:\17-workspace\11-Profile-Web\boyang167.github.io`。迁移完成后，网站仓库是唯一内容源，后续不再从原目录同步。

第一版交付一个适合 GitHub Pages 的文档型知识库，支持分类导航、文章目录、标签、中文和英文版本、全文搜索以及上一篇/下一篇导航。AI 问答、后台编辑器和数据库不在本期范围内。

## 已确认的内容策略

- 迁移所有可阅读的 Markdown 内容。
- 排除仅供生成流程使用的提示词、资源索引、重复 README 和非文章型文件。
- 同一内容的中文和英文版本均保留。
- 外部来源或非原创资料必须展示来源信息，避免被误认为原创。
- 图片等文章依赖资源随文档迁移；Notebook、独立 HTML 和其他二进制内容不作为第一版文章迁移。
- 原始目录在验收后不再作为维护源，但本次迁移不自动删除原目录。

## 方案选择

采用 Astro 原生内容集合与 Pagefind 静态索引。

与引入独立文档框架相比，该方案能延续现有个人网站的导航、视觉语言和部署流程。与运行时读取原始 Markdown 相比，构建期规范化内容能提供可靠的 schema 校验、静态 URL、链接检查和无后端全文搜索。

## 内容模型

沿用 `src/content/notes/` 作为知识库内容根目录，并保留有意义的主题层级。所有文章具有统一 frontmatter：

- `title`：文章标题。
- `description`：列表和搜索摘要。
- `date`：首次创建或可推断日期。
- `updated`：最后更新时间，可选。
- `area`：顶层知识领域。
- `tags`：主题标签。
- `language`：`zh-CN` 或 `en`。
- `translationKey`：中英文对应文章共享的稳定键，可选。
- `source`：外部来源 URL 或说明，可选。
- `draft`：是否从公开构建中排除。
- `order`：系列文章排序，可选。

文章 URL 由规范化后的相对路径生成。迁移后移动文件必须显式维护重定向或稳定 slug，避免链接无意变化。

## 迁移流程

一次性迁移工具扫描原目录并执行以下步骤：

1. 建立候选文件清单和明确排除清单。
2. 过滤提示词资源、重复索引、非 Markdown 文件和无独立阅读价值的片段。
3. 从首个一级标题、文件名和目录结构推断标题、知识领域、语言与排序。
4. 为缺少 frontmatter 的文件补齐规范字段；已有字段则校验并保留有效值。
5. 通过规范化标题和目录位置识别中英文对应关系，写入 `translationKey`。
6. 迁移本地图片并重写相对引用。
7. 重写可确定目标的内部 Markdown 链接。
8. 输出迁移报告，列出迁移、排除、冲突、缺图和失效链接。

同名目标、无法确定的语言对应关系、缺失本地资源和失效内部链接不得静默忽略；它们必须进入报告。同名目标仍使迁移校验失败。经本地文件、外部来源仓库和原 TechNotes 远端均无法恢复的图片改为正文内的明确缺失提示，失效内部链接改为不可用提示；二者作为警告保留，不阻止其余可阅读正文发布。

## 页面与交互

知识库首页展示领域、文章数量、常用标签和最近更新，并提供搜索入口。桌面端采用三栏阅读布局：

- 左栏：按领域和系列生成的分类树。
- 中栏：文章元数据、正文、语言切换和前后导航。
- 右栏：根据二级、三级标题生成的文章目录。

移动端将左右导航折叠为可打开的面板，正文保持单栏。文章页显示面包屑、语言、标签、更新时间及来源提示。中英文对应文章可直接互相切换。

## 搜索

Astro 构建完成后运行 Pagefind，为公开文章的标题、摘要、标签和正文建立静态索引。搜索在浏览器端工作，不依赖服务器或 API，兼容 GitHub Pages。草稿和明确排除的页面不得进入索引。

## 组件边界

- 内容集合 schema：负责元数据类型和构建期校验。
- 迁移工具：只负责一次性导入、资源复制、链接重写和报告，不参与网站运行。
- 知识库导航模块：从集合元数据生成分类树、面包屑和相邻文章。
- 文章布局：负责三栏页面、元数据、目录、语言切换和来源提示。
- 搜索页面：负责加载 Pagefind 并呈现搜索结果。

各模块通过规范化内容模型交互，不依赖迁移目录的原始命名细节。

## 异常处理

- schema 缺失或类型错误：Astro 检查失败。
- 重复 slug 或目标路径：迁移失败并报告冲突双方。
- 缺失图片或无法解析的本地链接：尝试多个确定来源恢复；最终无法恢复时写入正文提示和迁移警告。
- 无法识别标题或语言：使用明确的回退值并在报告中标记人工复核。
- Pagefind 索引失败：构建失败，避免部署一个宣称支持搜索但不可搜索的网站。

## 验证与验收

- 迁移文件数、排除文件数与报告一致，且每个排除项有原因。
- 所有公开文档通过内容 schema 校验。
- 不存在重复 URL；无法恢复的内部链接和图片均已转换为明确提示并记录在报告中。
- 中英文对应文章可双向切换。
- 分类树、目录、标签和前后导航在桌面端与移动端可用。
- 搜索可命中文章标题、标签和正文中的中英文关键词。
- `astro check`、生产构建和 Pagefind 索引均成功。
- GitHub Pages 部署产物中的路径和静态资源可正常访问。

## 实施边界

本次实现修改个人网站仓库并迁入内容，不删除 `3-TechNotes` 原目录。待用户核对线上内容后，可另行归档或删除原目录。任何无法确认发布权利的内容会保留来源提示并进入迁移报告，由用户最终决定是否公开。
